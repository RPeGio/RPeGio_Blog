## 为什么开始关注 ESA Pages

个人博客这类纯静态站点，过去要么自己买一台小机器装 Nginx，要么用 GitHub Pages 之类的托管。前者要操心证书、备份和续费，后者在国内访问速度一般，也没有统一的构建与版本管理。

阿里云 ESA（边缘安全加速）里的「函数和 Pages」把这套流程收进了一个控制台：把 GitHub 仓库连上去，平台自动构建、自动发布到边缘节点，静态资源和边缘函数（V8 Isolate）可以放在同一个项目里。对前端项目来说，最直观的好处是不用自己维护 CI 和 CDN 回源链路；对国内访问来说，ESA 本身还带 WAF、DDoS 防护和缓存规则，安全能力和分发能力是同一套体系。

## 本站的技术栈

本站是 Astro 6 的静态站点：文章写在 `src/content/blog/` 下的 Markdown 里，`npm run build` 产出 `dist/`，没有服务端逻辑。这种「构建产物是一堆静态文件」的项目，是 Pages 最典型的适用场景，也正好拿来当部署示例。

## 部署流程

### 1. 开通与添加站点

ESA Entrance 版在国际站长期免费，注册账号后进入 ESA 控制台添加站点即可。默认不包含中国内地加速，只在境外节点分发；如果需要大陆访问，可以在控制台把加速区域切换为全球（Entrance 版需要通过官方活动解锁中国内地加速，具体以控制台提示为准）。

### 2. 接入 GitHub 仓库

在控制台左侧选择「边缘计算和 AI」→「函数和 Pages」→ 创建 Pages，授权 GitHub 后选择仓库和分支。之后每次向该分支 push，平台都会自动拉取代码、执行构建并发布。

### 3. 填写构建信息

以本站为例，构建配置大致是这几项：

| 配置项     | 值                             |
| ---------- | ------------------------------ |
| 根目录     | `/`                            |
| 安装命令   | `npm ci`                       |
| 构建命令   | `npm run build`                |
| 静态资源目录 | `./dist`                     |
| Node 版本  | 按 `package.json` 的 engines 选 |

构建信息可以在控制台里改，也可以直接写进仓库根目录的 `esa.jsonc`。

### 4. 用 esa.jsonc 固化配置

`esa.jsonc` 是「基础设施即代码」的入口，配置跟着代码一起走，回滚时构建环境也能一起回滚。需要注意它的优先级高于控制台：仓库里一旦存在这个文件，控制台里对应的构建选项就不再生效。

```jsonc title="esa.jsonc"
{
  "name": "rpegio-blog",
  "installCommand": "npm ci",
  "buildCommand": "npm run build",
  "assets": {
    "directory": "./dist",
    "notFoundStrategy": "404Page"
  }
}
```

- `name`：部署的目标项目名，项目不存在时会自动创建。
- `installCommand` / `buildCommand`：安装与构建命令，支持 npm、pnpm、yarn、cnpm、bun；留空则跳过该步骤。
- `assets.directory`：构建产物中作为静态资源托管的目录。
- `assets.notFoundStrategy`：静态资源未命中时的策略。

### 5. 路由与尾斜杠

`notFoundStrategy` 有三档，按项目类型选就行：

- 不填（默认模式）：有对应静态文件就直接返回，没有则交给边缘函数，再没有就 404。
- `singlePageApplication`：导航请求回落到 `index.html`，适合 Vue/React 的 SPA。
- `404Page`：未命中时返回 `404.html`，适合静态站点生成，本站这类站点用这一档。

另一个容易忽略的点是**尾斜杠**：Pages 默认会把目录路径重定向到带斜杠的形式，比如访问 `/blog` 会跳到 `/blog/`。而本站 Astro 配置里是 `trailingSlash: 'never'`，站内链接本来就不带斜杠，两者叠加后会出现一次额外跳转。这不影响正确性，但如果很在意首屏请求数，可以把站点配置和平台行为对齐，或者干脆让 Astro 输出带斜杠的链接。

### 6. 绑定域名

项目创建后会先给一个默认域名。自定义域名解析到 ESA 后，平台会自动签发和续期 HTTPS 证书，域名流量也就顺带接入了 ESA 的缓存与安全策略。

## 能力边界

官方文档给出了几组明确的限制，部署前值得先对照一遍：

| 项目           | 限制                          |
| -------------- | ----------------------------- |
| Pages 静态文件数 | 2000 个                       |
| 单个文件大小   | 25MB                          |
| 项目压缩包     | 1024MB                        |
| 边缘函数代码包 | 4MB                           |
| 函数响应时间   | 120 秒（含等待 I/O）          |
| 网关等待函数   | 10 秒，超时返回 504           |
| 单次函数子请求 | 4 个                          |
| 函数语言       | JavaScript（ES6）             |

对一个博客或者文档站来说，这些额度绰绰有余：本站构建产物只有几百 KB 到几 MB，文件数也远不到 2000。真正会碰到限制的，是往仓库里塞大视频、或者把重型 SSR 逻辑压进边缘函数的项目。

## 适合谁，什么情况再等等

适合接入的是这几种：

- 纯静态博客、文档站、作品集，构建一次就能长期托管。
- 前后端分离的 SPA，只需要一条 fallback 规则。
- 想在同一个项目里放静态页面和少量边缘逻辑（比如鉴权、重定向、A/B 分流）。
- 已经在用阿里云 ESA 做 CDN 或安全防护的站点，可以直接复用域名和证书体系。

需要再评估的是：依赖长任务或大量内部请求的服务端应用，受 10 秒网关等待和 4 个子请求的限制；需要把超大依赖打进函数包的项目，4MB 的上限会很快成为瓶颈。

## 小结

ESA Pages 的思路和主流 Pages 平台一致：把构建、发布、分发、安全收敛成一条流水线，开发者只管往主分支 push。它的差异点在于和 ESA 的安全与加速能力是同一套底座，域名接进来之后不需要再单独配置一层 CDN。对个人项目来说，Entrance 版免费、按分支自动构建，试错成本很低；把 `esa.jsonc` 放进仓库，配置也能跟着代码一起版本化。

如果你的博客也是 Astro、Hexo 或 VitePress 这类静态生成器，基本改一下安装命令和输出目录就能跑通，值得花半小时试一次。
